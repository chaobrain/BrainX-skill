# Product

## Register

brand

## Platform

web

## Users

Researchers, computational neuroscientists, and developers evaluating whether a general coding agent can turn a natural-language neuroscience question into a precise, runnable BrainX experiment. Readers need to inspect the prompt, the agent's modeling decisions, the generated evidence, and eventually a controlled skill-versus-baseline comparison.

## Product Purpose

Show how the portable BrainX skill turns research intent into unit-aware, transform-compatible BrainX simulations. Success means a reader can move from the quick start to a named experiment, see the exact source prompt and result, and audit the selected run without promotional interpretation replacing evidence.

## Positioning

The agent translates the research question; explicit BrainX code controls and executes the dynamics.

## Conversion & proof

- Primary action: install the BrainX skill and inspect the experiment cases.
- Secondary action: open a case page and audit its prompt, decision trace, source log, code, and result.
- The line a visitor remembers after 10 seconds: natural language becomes an explicit BrainX experiment whose result is computed by code.
- Belief ladder: the skill is portable; it routes intent to the correct modeling scale; BrainX owns numerical execution; the committed artifacts make the claim auditable.
- Proof on hand: the exact prompts, selected agent event logs, generated source, verification summaries, and result figures under `brainx-display-cases/`.

## Brand Personality

Sharp, scientific, and restrained. The documentation should feel like a calm research workbench: evidence-led, readable, and visibly part of the BrainX ecosystem.

## Anti-references

Do not make this a marketing landing page, a decorative dashboard, or a card wall. Avoid unsupported superlatives, invented benchmark claims, hidden primary evidence, decorative plots, duplicate navigation chrome, and visual treatments that compete with the scientific outputs.

## Design Principles

1. Put the exact research question before the implementation narrative.
2. Keep the modeling decision path short enough to scan and precise enough to audit.
3. Place generated evidence beside the conclusion it supports.
4. Distinguish measured results from planned comparisons or missing artifacts.
5. Preserve progressive disclosure: show the canonical story first and link to complete logs and code for depth.

## Accessibility & Inclusion

Meet WCAG AA contrast, preserve semantic heading order, provide meaningful figure descriptions, keep code and tables usable on mobile, expose visible keyboard focus, use at least 44 px touch targets, and honor reduced-motion preferences.
